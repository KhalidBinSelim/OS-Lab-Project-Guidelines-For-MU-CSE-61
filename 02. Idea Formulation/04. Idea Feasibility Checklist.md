# 04 · Idea Feasibility Checklist

Answer **honestly** before submitting your proposal. Each "No" is a risk.

## A. Clarity
- [ ] I can state the project in **one sentence**.
- [ ] I can name the **primary OS concept** and explain it without notes.
- [ ] I know what the user **inputs** and what they **see**.

## B. Size
- [ ] The **Must-have** list can be finished in **≤ 2 weeks**.
- [ ] Total planned code is roughly **800–2500 lines** (not 10,000).
- [ ] It works in a **terminal**.
- [ ] It needs **no special hardware / paid service**.

## C. Understanding
- [ ] Every teammate can learn the required theory within **1 week**.
- [ ] I can trace the main algorithm by hand on paper.
- [ ] I know which **system calls / libraries** are needed.

## D. Demonstrability
- [ ] A **3-minute demo** shows the key idea.
- [ ] There are **sample inputs** with known expected outputs.
- [ ] If the live demo fails, I have **screenshots / a recording** as backup.

## E. Testability
- [ ] I can write at least **10 test cases** with expected results.
- [ ] Failure cases (bad input, empty input) are defined.

## F. Originality
- [ ] My project has **at least one exception** beyond the demo idea.
- [ ] My repo will be different from other teams' repos.

## Scoring
| "No" answers | Meaning |
|--------------|---------|
| 0 to 1 | ✅ Go ahead |
| 2 to 3 | ⚠️ Shrink scope or clarify first |
| 4+ | ❌ Choose a simpler idea |
