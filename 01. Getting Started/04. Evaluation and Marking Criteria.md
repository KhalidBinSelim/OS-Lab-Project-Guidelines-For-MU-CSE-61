## Likely Evaluation Areas (Tentative)

| Area | What examiners look for usually |
|------|-------------------------|
| **Idea & OS relevance** | Does the project clearly demonstrate real OS concepts? |
| **Implementation** | Correctness, completeness, working features |
| **Code quality** | Structure, readability, comments, error handling |
| **Understanding (Q/A)** | Can you explain any line, concept, and design choice? |
| **GitHub practice** | Commit history, branches, PRs, issues, README |
| **Documentation** | README, design docs, user guide, test report |
| **Presentation & demo** | Clarity, time management, live demo success |
| **Teamwork / individual contribution** | Fair split, evidence of each member's work |
| **Responsible AI use** | AI log, ability to explain AI-assisted code |

## How To Protect Your Marks (Regardless of Final Rubric)

1. **Make it run first.** A failing demo hurts every category.
2. **Be able to explain everything.** Q/A usually carries heavy weight.
3. **Show history.** Regular commits from every member.
4. **Document honestly.** State what works, what does not, and why.
5. **Respect time limits** in the presentation.
