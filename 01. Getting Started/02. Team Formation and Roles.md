# 02 · Team Formation and Roles
<!--
> Team size will be fixed with commonly **1 to 3 members**.
-->
## 1. Choosing Teammates
Choose people who:
- Can meet **at least 3 times a week** (online or offline).
- Have **similar commitment** to the project.
- Have **different strengths** (one comfortable with C, one with testing/docs, etc.).

Agree in writing (a short message in your group chat is enough) on:
- Weekly meeting time
- How fast you reply
- What happens if someone stops contributing (tell the instructor **early**)

## 2. Suggested Roles
In small teams, one person may hold multiple roles, but **everyone codes and everyone learns everything**.

| Role | Responsibilities |
|------|------------------|
| **Tech Lead** | Architecture decisions, merges PRs, keeps `main` working |
| **Core Developer(s)** | Implements main OS logic |
| **QA / Test Owner** | Writes test cases, runs tests, maintains the test report |
| **Docs & Demo Owner** | README, diagrams, slides, demo script |
| **Git Captain** | Branch rules, issue board, release tag |

> 🔁 **Rotate** the review role: whoever *wrote* a feature must **not** be the only one who *reviews* it.

## 3. Cross-Teaching Rule
Because anyone can be asked about anything, hold a **weekly 20-minute "teach-back"**:
- Each member explains one module to the others **without looking at code**.
- Note what was unclear → fix it before the next week.

## 4. If a Teammate Is Not Contributing
1. Talk to them directly, kindly, with specifics.
2. Re-assign tasks on the issue board.
3. If it continues, inform **with evidence** (GitHub history / issue board). Do not wait until the last week.
