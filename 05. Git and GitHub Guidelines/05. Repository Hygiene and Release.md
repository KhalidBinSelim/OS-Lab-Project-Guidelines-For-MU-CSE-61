# 05 · Repository Hygiene and Release

## 1. `.gitignore` for C Projects
```gitignore
# Build output
build/
*.o
*.out
*.exe
*.a
*.so

# Debug / profiling
*.dSYM/
core
vgcore.*
*.log
trace.txt

# Editors / OS
.vscode/
.idea/
*.swp
.DS_Store

# Runtime artifacts (adjust per project)
disk.img
*.tmp
```
> If your project needs a sample `disk.img` or logs in the repo, commit a **small** example under `examples/` instead.

## 2. Never Commit
- Compiled binaries
- Passwords, tokens, API keys, private keys
- Large files (> 10 MB) or videos (link them instead)
- Personal data of other people

If you commit a secret by accident: **revoke it immediately** (changing history alone is not enough).

## 3. Files Every Repo Needs
| File | Purpose |
|------|---------|
| `README.md` | Build/run/demo |
| `LICENSE` | Usage rights (MIT is fine) |
| `.gitignore` | Keep junk out |
| `docs/…` | Required documents |
| `Makefile` | One-command build |
| `.github/…` | PR + issue templates |

## 4. Repository Settings To Check
- Description (one line) and **topics**: `operating-system`, `c`, `linux`, `university-project`
- Social preview/screenshot in README
- Collaborators: teammates + instructor
- Issues and Projects enabled
- Branch protection for `main`

## 5. README Polish Checklist
- [ ] Project title and one-sentence description
- [ ] Screenshot or GIF of the demo (`asciinema` or screen recorder)
- [ ] Badges (optional): language, license
- [ ] Prerequisites, build, run, test commands (copy-paste ready)
- [ ] Feature list + known limitations
- [ ] Project structure tree
- [ ] Team members with IDs and GitHub usernames
- [ ] Links to `/docs`

## 6. Release (Final Submission)
1. Make sure `main` builds and tests pass on a **fresh clone**.
2. Tag:
```bash
git tag -a v1.0-final -m "Final submission"
git push origin v1.0-final
```
3. GitHub → **Releases → Draft a new release** → choose tag `v1.0-final` → add short notes (features, how to run) → attach `slides.pdf` and a demo video link if available.
4. Submit the **repo link** and the **release/tag name** as instructed.
5. After submission: **do not push to `main`** unless allowed. The instructor may review the history up to the deadline.

## 7. Fresh-Clone Test (Do It Twice)
```bash
cd /tmp
git clone <your-repo-url> test-clone
cd test-clone
make
make test
./build/app --help
```
If any step fails, a stranger cannot run your project either.
