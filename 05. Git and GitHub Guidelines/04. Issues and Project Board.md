# 04 · Issues and Project Board

## 1. Use Issues as Your Task List
**One issue = one task of ≤ 1 day.** Issues show examiners your planning and teamwork.

### Good Issue Titles
- `Implement FCFS scheduling algorithm`
- `Add input validation for negative burst time`
- `Bug: shell hangs on pipe with grep`
- `Write README build instructions`

### Issue Body Template
```markdown
**Goal:** what should be done
**Acceptance criteria:**
- [ ] ...
- [ ] ...
**OS concept:** ...
**Priority:** Must / Should / Could
**Estimate:** 3h
```
Templates for bugs and features are in `.github/ISSUE_TEMPLATE/`.

## 2. Labels
Create these in **Issues → Labels**:

| Label | Color idea | Meaning |
|-------|-----------|---------|
| `must` | 🔴 | Must-have |
| `should` | 🟠 | Should-have |
| `could` | 🟡 | Could-have |
| `bug` | 🟥 | Something broken |
| `docs` | 🔵 | Documentation |
| `test` | 🟣 | Tests |
| `blocked` | ⚫ | Waiting on something |
| `good-first-task` | 🟢 | Easy starter task |

## 3. Milestones
Create one per week:
- `Week 1 – Foundations`
- `Week 2 – MVP`
- `Week 3 – Features & Tests`
- `Week 4 – Polish & Submit`

Assign each issue to a milestone. The percentage bar shows progress instantly.

## 4. Project Board (Kanban)
GitHub → **Projects → New project → Board**.

| Column | Meaning |
|--------|---------|
| Backlog | Not started |
| This Week | Planned for current sprint |
| In Progress | Someone is working on it (assign them) |
| In Review | PR open |
| Done | Merged and verified |

Rules:
- Max **2 items In Progress** per person.
- Move cards yourself; do it daily.
- Link PRs to issues so cards move automatically.

## 5. Workflow Summary
```
Issue created → assigned → branch feature/x → commits → PR "Closes #n" → review → merge → issue auto-closes
```

## 6. Weekly Review
In Every Weekend:
1. Close finished issues.
2. Move unfinished to next week or **cut** them.
3. Add newly discovered tasks.
4. Take a screenshot of the board for your weekly progress report.
