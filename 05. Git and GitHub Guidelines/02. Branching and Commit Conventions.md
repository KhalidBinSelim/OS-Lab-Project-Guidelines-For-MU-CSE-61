# 02 · Branching and Commit Conventions

## 1. Branch Strategy (Simple GitHub Flow)

```
main      ──●───────●────────●───────●──►   stable, always runs
             \     /  \     /
feature/fcfs  ●──●     ●──●  feature/round-robin
```

| Branch | Purpose | Rules |
|--------|---------|-------|
| `main` | Always working, demo-ready | Only via reviewed PR |
| `feature/<name>` | New feature | Branch from `main`, short-lived (1–3 days) |
| `fix/<name>` | Bug fix | Same as above |
| `docs/<name>` | Documentation only | Same |
| `test/<name>` | Tests | Same |

### Naming Examples
`feature/round-robin` · `fix/pipe-fd-leak` · `docs/readme-usage` · `test/belady-cases`

### Protect `main` (Recommended)
GitHub → Settings → Branches → **Add rule** for `main`:
- ✅ Require a pull request before merging
- ✅ Require at least 1 approval
- ✅ Dismiss stale approvals (optional)

## 2. Commit Message Convention
Format:
```
<type>(<scope>): <short summary in present tense>

<optional longer explanation: what and why>
```

### Types
| Type | Use for |
|------|---------|
| `feat` | New feature |
| `fix` | Bug fix |
| `docs` | Documentation |
| `test` | Tests |
| `refactor` | Restructure without changing behavior |
| `style` | Formatting only |
| `build` | Makefile, build config |
| `chore` | Misc maintenance |

### Examples
```
feat(scheduler): add Round Robin with configurable quantum
fix(shell): close unused pipe ends to prevent hang
docs(readme): add build and run instructions
test(memory): add Belady's anomaly test case
refactor(parser): split tokenizer into its own file
```

### Bad Messages ❌
`update` · `fix` · `changes` · `asdf` · `final` · `final2`

## 3. Commit Rules
1. One commit = **one logical change**.
2. The project should **compile** at every commit on `main`.
3. Message ≤ 72 characters in the first line.
4. Reference issues: `feat(fcfs): add FCFS (#4)` or `Closes #4` in the body.
5. If AI helped substantially, add a line in the body: `AI-assisted: yes (see docs/AI_USAGE_LOG.md#entry-7)`.

## 4. Merge Conflicts (They Will Happen)
```bash
git switch feature/x
git merge main              # conflict appears
# open conflicted file; look for <<<<<<< ======= >>>>>>>
# edit to the correct final content, remove markers
git add <file>
git commit
```
Prevention: small branches, merge `main` into your branch daily, don't edit the same file as a teammate at the same time without talking.

## 5. Tags and Milestones
```bash
git tag -a v0.1-mvp -m "MVP demo works"
git push origin v0.1-mvp
```
Suggested tags: `v0.1-mvp` (Week 2) · `v0.9-feature-complete` (Week 3) · `v1.0-final` (submission).
