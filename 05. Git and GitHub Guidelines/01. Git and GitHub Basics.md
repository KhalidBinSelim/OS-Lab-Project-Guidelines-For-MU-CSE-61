# 01 · Git and GitHub Basics

## 1. What Are Git and GitHub?
- **Git** = version control tool on your computer (history of every change).
- **GitHub** = website that hosts your Git repository online for sharing, review, and submission.

Why we use it: backup · teamwork · proof of **who did what** · professional skill.

## 2. Key Words

| Term | Meaning |
|------|---------|
| Repository (repo) | Project folder tracked by Git |
| Commit | A saved snapshot with a message |
| Branch | A parallel line of work |
| Merge | Combine branches |
| Remote (`origin`) | The GitHub copy |
| Clone | Download a repo |
| Push / Pull | Upload / download commits |
| Pull Request (PR) | Request to merge your branch, with review |
| Issue | A task/bug/idea ticket |

## 3. One-Time Setup
1. Create an account at github.com (use a professional username).
2. Enable **two-factor authentication**.
3. Set up SSH key **or** use HTTPS with a Personal Access Token:
```bash
ssh-keygen -t ed25519 -C "your.email@example.com"
cat ~/.ssh/id_ed25519.pub     # paste into GitHub → Settings → SSH keys
ssh -T git@github.com         # test
```

## 4. Create Your Project Repo

**Team Tech Lead only:**
1. GitHub → **New repository**
2. Name: `os-lab-project-<short-name>` (e.g., `os-lab-project-cpu-scheduler-sim`)
3. Visibility: as instructed (usually **Public** or add instructor as collaborator)
4. Add **README**, **.gitignore (C)**, **License (MIT)**
5. Settings → Collaborators → add teammates and instructor

**Everyone:**
```bash
git clone git@github.com:<owner>/os-lab-project-<short-name>.git
cd os-lab-project-<short-name>
```

## 5. Daily Commands (Cheat Sheet)

```bash
git status                       # what changed?
git pull origin main             # get latest
git switch -c feature/fcfs       # new branch
# ... edit files ...
git add src/fcfs.c include/fcfs.h
git commit -m "feat(scheduler): add FCFS algorithm"
git push -u origin feature/fcfs  # first push of a branch
# then open a Pull Request on GitHub
```

| Task | Command |
|------|---------|
| See history | `git log --oneline --graph --decorate` |
| See changes | `git diff` / `git diff --staged` |
| Undo unstaged changes in a file | `git restore <file>` |
| Unstage a file | `git restore --staged <file>` |
| Switch branch | `git switch <branch>` |
| Update branch with main | `git switch feature/x && git merge main` |
| Temporarily save work | `git stash` / `git stash pop` |
| Fix last commit message | `git commit --amend` (only before pushing) |
| See who wrote a line | `git blame src/fcfs.c` |

## 6. Good Habits
- Commit **small, logical changes** (not "final final v3").
- **Pull before you push** and before starting work.
- **Never commit** compiled binaries, `.o` files, secrets, or huge files.
- **Never** `git push --force` to `main`.
- Write commit messages a stranger can understand.

## 7. Using the Commit History as Evidence
Your commit history shows examiners your **individual contribution** and **working pattern**:
- Regular commits across weeks ✅
- Commits from **every** team member ✅
- One giant commit on the last night ❌ (looks suspicious)

Make sure `git config user.name/email` matches your GitHub account so commits are attributed to you.
