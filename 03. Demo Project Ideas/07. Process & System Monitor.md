# Idea 07 · Process & System Monitor (Mini `htop`)

## 1. Overview
A terminal tool that reads live OS data from the **`/proc`** virtual file system and shows running processes, CPU usage, and memory usage. Users can sort, filter, and send signals.

**Difficulty:** ⭐⭐ · **Language:** C (Linux/WSL2) · **Best for:** impressive live demos with real data

## 2. OS Concepts Covered
Process control block in real life · process states (R, S, D, Z, T) · PID/PPID · CPU time (`utime`, `stime`) · virtual vs resident memory · `/proc` · signals · process tree

## 3. Features

### Must
- List all processes: PID, name, state, PPID, memory (RSS)
- Parse `/proc/<pid>/stat` and `/proc/<pid>/status` correctly
- Auto-refresh every N seconds
- System summary from `/proc/meminfo` (total, used, free)

### Should
- **CPU % per process** (difference of ticks between two samples)
- Sort by CPU / memory / PID / name
- Filter by name or user
- Kill a process by PID with a chosen signal (with confirmation)

### Could
- Process tree view (using PPID)
- Count of zombie/sleeping/running processes with warnings
- Log high-CPU events to a file
- Interactive keyboard control with `ncurses`

## 4. Suggested Design
```
src/
├── main.c           # refresh loop
├── proc_reader.c    # reads & parses /proc entries
├── cpu_stats.c      # sampling & % calc (/proc/stat)
├── mem_stats.c      # /proc/meminfo
├── display.c        # table printing / ncurses
└── control.c        # kill, sort, filter
```
Directory scan: `opendir("/proc")` and keep entries with numeric names.

## 6. Demo Scenario
1. Run monitor → show process list.
2. In another terminal run `yes > /dev/null &` → watch CPU spike to ~100%.
3. Kill it from your tool with `SIGTERM`.
4. (Twist) Create a zombie with a small C program → monitor shows `Z` state.

## 7. You Must Be Able To Explain
- What `/proc` is (not a real disk; kernel exposes info as files)
- The meaning of the fields in `/proc/<pid>/stat` you parse (and **why** process names with spaces/parentheses need careful parsing)
- How CPU% is calculated: `Δ(process ticks) / Δ(total ticks)`
- Process states and what a zombie is
- What `kill` really does (sends a signal; process may handle it)

## 8. Pitfalls
- Parsing `stat` with `sscanf` when the name has spaces
- Race: process disappears mid-scan → handle `fopen` failure
- Dividing by zero on first sample
- Not closing directories/files (resource leaks)
- On Windows without WSL2 `/proc` does not exist

## 9. Exceptions
Alert thresholds with sound/color · export snapshot to JSON · compare "before vs after" runs · security view (processes with open network ports)
