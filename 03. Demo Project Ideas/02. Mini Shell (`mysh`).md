# Idea 02 · Mini Shell (`mysh`)

## 1. Overview
A Unix-like command interpreter written in C that reads commands, creates child processes, and supports built-ins, redirection, pipes, and background execution.

**Difficulty:** ⭐⭐⭐ · **Language:** C on Linux · **Best for:** students who want the strongest "real OS" demo

## 2. OS Concepts Covered
Process creation (`fork`) · program loading (`exec`) · `wait`/zombie processes · file descriptors · `dup2` · pipes · signals · environment variables

## 3. Features

### Must
- Prompt loop with input parsing (tokenization)
- Run external programs (`fork` + `execvp` + `waitpid`)
- Built-ins: `cd`, `exit`, `pwd`, `help`
- Handle `command not found` and empty input

### Should
- Output/input redirection: `>`, `>>`, `<`
- One pipe: `ls | wc -l`
- Background jobs with `&` (and reaping zombies)
- Handle `Ctrl+C` so the shell survives but the child stops (`SIGINT`)

### Could
- Multiple pipes (`a | b | c`)
- Command history (`history`, `!!`)
- `jobs` list, environment variables (`export`, `$VAR`)
- Colored prompt with current directory

## 4. Suggested Design
```
src/
├── main.c        # REPL loop
├── parser.c      # tokenize line → struct Command
├── executor.c    # fork/exec, redirection, pipes
├── builtins.c    # cd, exit, pwd, help, history
├── signals.c     # SIGINT / SIGCHLD handlers
└── jobs.c        # background job table
```
`struct Command { char *argv[64]; char *infile, *outfile; int append, background; struct Command *next; }`

## 5. Four-Week Plan
| Week | Goal |
|------|------|
| 1 | REPL, tokenizer, `fork`/`exec`/`wait`, `cd`/`exit` |

## 6. Demo Scenario
```
mysh> ls -l | grep ".c" > cfiles.txt
mysh> cat cfiles.txt
mysh> sleep 10 &
mysh> jobs
mysh> cd .. && pwd
```
Show `ps` in another terminal to prove child processes exist; show **no zombies**.

## 7. You Must Be Able To Explain
- What exactly `fork()` returns in parent and child, and why
- Why `cd` **must** be built-in (it changes the *shell's* own process)
- How `pipe()` + `dup2()` connect two processes (draw the file-descriptor diagram)
- What happens if you forget to close unused pipe ends (hangs!)
- Zombie vs orphan processes; how `waitpid` / `SIGCHLD` prevent zombies

## 8. Pitfalls
- Memory leaks in the tokenizer (use `valgrind`)
- Not closing pipe ends → program hangs
- Forgetting `waitpid` → zombie processes
- Buffer overflows with fixed input size → use `fgets` and check length
- Child continuing the shell loop after failed `exec` → always `exit(1)` in the child

## 9. Exceptions
Command aliases · tab-less autocomplete of built-ins · execution-time display · logging all commands with timestamps · safe-mode that blocks dangerous commands
