# Idea 05 · Process Synchronization Lab (Race Conditions → Semaphores)

## 1. Overview
A collection of **multi-threaded demos** in C that first **show the bug** (race condition, deadlock) and then **fix it** with mutexes/semaphores: Producer–Consumer, Readers–Writers, Dining Philosophers, plus a shared bank-account example.

**Difficulty:** ⭐⭐⭐ · **Language:** C with `pthread` and POSIX semaphores · **Best for:** strong "see the bug happen" demos

## 2. OS Concepts Covered
Threads · critical section · race condition · mutual exclusion · mutex · semaphores · bounded buffer · starvation · deadlock avoidance

## 3. Features

### Must
- **Race condition demo:** N threads increment a shared counter without a lock → wrong total; then with a mutex → correct total
- **Producer–Consumer** (bounded buffer) using semaphores + mutex
- Command-line menu to select scenario and parameters (threads, buffer size, iterations)
- Clear timestamped log of events

### Should
- **Dining Philosophers**: naive version (deadlocks) + fixed version (resource ordering or limit 4 philosophers)
- **Readers–Writers**: reader-priority version and note starvation
- Statistics: throughput, wait times, number of blocked operations
- Deterministic "slow-motion" mode using `usleep` to make behavior visible

### Could
- Writer-priority / fair readers–writers
- Terminal animation of philosophers' states
- Compare mutex vs semaphore vs spinlock performance
- Barrier / sleeping barber

## 4. Suggested Design
```
src/
├── main.c               # menu
├── race_demo.c
├── producer_consumer.c
├── readers_writers.c
├── dining_philosophers.c
├── logger.c             # thread-safe timestamped logging

```
Compile: `gcc -Wall -Wextra -pthread ...` · Tip: log through **one** mutex-protected function so output is not interleaved.

## 6. Demo Scenario
1. Run race demo: expected 1,000,000 but got 538,214 → **show the bug**.
2. Add mutex → exactly 1,000,000.
3. Run naive philosophers → freeze (deadlock) → run fixed version → continues forever.
4. Show producer–consumer log: buffer never overflows or underflows.

## 7. You Must Be Able To Explain
- Why `counter++` is **not atomic** (load–add–store, with interleaving example)
- What each semaphore (`empty`, `full`, `mutex`) counts and why initial values are what they are
- Why the **order** of `sem_wait` calls matters (deadlock if swapped)
- How your philosopher fix breaks one of the 4 deadlock conditions
- Difference between mutex and semaphore

## 8. Pitfalls
- Tests that pass by luck (race bugs are non-deterministic → repeat runs)
- Forgetting `-pthread`
- Passing a loop variable's address to threads (all threads see the same `i`)
- Unsynchronized `printf` mixing outputs
- Not destroying/initializing semaphores properly

## 9. Exceptions
"Bank transfer" deadlock scenario · thread-safe ring buffer library · auto-detect deadlock by timeout watchdog thread
