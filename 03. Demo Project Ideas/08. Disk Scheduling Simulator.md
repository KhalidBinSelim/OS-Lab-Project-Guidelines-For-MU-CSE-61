# Idea 08 · Disk Scheduling Simulator

## 1. Overview
Simulates how a disk controller orders **cylinder requests** to minimize head movement. A lighter project — **ideal for beginners or as a second module** in a combined project.

**Difficulty:** ⭐ · **Language:** C or Python

## 2. OS Concepts Covered
Disk structure (cylinders, seek time) · FCFS · SSTF · SCAN (elevator) · C-SCAN · LOOK · C-LOOK · starvation · throughput

## 3. Features

### Must
- Input: request queue, initial head position, disk size, direction
- FCFS, SSTF, SCAN, C-SCAN
- Output: service order, **total head movement**, average seek
- Text visualization of head path (e.g., list of arrows or an ASCII graph)

### Should
- LOOK and C-LOOK
- Comparison table of all algorithms on the same input
- Input validation (request within disk range)
- Random workload generator (uniform, clustered, sequential)

### Could
- Simulate request **arrival times** (dynamic queue)
- Plot head movement graph (Python `matplotlib` or SVG)
- Starvation demo for SSTF
- Seek-time model (`seek = a + b·√distance`)

## 4. Suggested Design

src/

## 6. Demo Scenario
Queue `98 183 37 122 14 124 65 67`, head at 53, disk 0–199: show total movements for each algorithm, then explain why SSTF is good but can starve far requests.

## 7. You Must Be Able To Explain
- Why SCAN goes to the end of the disk but LOOK stops at the last request
- Why C-SCAN gives more uniform waiting time
- Why disk scheduling matters less for SSDs
- How you handle direction changes

## 8. Pitfalls
- Sorting the original queue instead of a copy
- Forgetting the jump back in C-SCAN (count or not count it? **document your choice**)
- Mixing up direction conventions

## 9. Exceptions
Merge with Idea 01 into a "full scheduling suite" · benchmark which algorithm wins for each workload type
