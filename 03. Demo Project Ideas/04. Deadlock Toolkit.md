# Idea 04 · Deadlock Toolkit (Banker's + Detection + Recovery)

## 1. Overview
An interactive tool that models **resources and processes**, checks whether the system is in a **safe state**, handles **resource requests**, **detects deadlocks**, and suggests **recovery**.

**Difficulty:** ⭐⭐ · **Language:** C or Python

## 2. OS Concepts Covered
Deadlock conditions (mutual exclusion, hold & wait, no preemption, circular wait) · Safe/unsafe states · Banker's algorithm · Resource Allocation Graph · wait-for graph · cycle detection · recovery (termination/preemption)

## 3. Features

### Must
- Input: `Allocation`, `Max`, `Available` matrices from file/manual entry
- Compute `Need = Max − Allocation`
- **Safety algorithm** with the **safe sequence** printed step by step
- **Resource-request algorithm** (grant / deny / wait, with reason)

### Should
- Deadlock **detection** (for multiple instances)
- Wait-for graph cycle detection (single instance per resource)
- Recovery suggestions: which process to terminate (cost-based)
- Input validation (Max ≥ Allocation, non-negative)

### Could
- ASCII/Graphviz drawing of resource allocation graph
- Random scenario generator ("create a deadlock")
- Compare avoidance vs detection side-by-side
- Interactive "what-if" mode

## 4. Suggested Design
```
src/
├── main.c
├── banker.c         # need, safety, request
├── detection.c      # detection algorithm
├── graph.c          # wait-for graph, DFS cycle detection
├── recovery.c
└── io.c             # load/print matrices
examples/            # safe.txt, unsafe.txt, deadlock.txt
```

## 6. Demo Scenario
1. Load a safe system → show safe sequence `P1 → P3 → P4 → P0 → P2`.
2. Process makes a request that leads to an **unsafe** state → denied with explanation.
3. Load a deadlocked system → detect which processes are stuck → propose recovery.

## 7. You Must Be Able To Explain
- Why "safe state" ≠ "no deadlock right now" and "unsafe" ≠ "deadlocked"
- Every step of your `Work`/`Finish` loop in the safety algorithm
- Difference between prevention, avoidance, detection, recovery
- Why Banker's is rarely used in real OSs

## 8. Pitfalls
- Confusing rows (processes) and columns (resources)
- Not restoring state after a **tentative** allocation is rejected
- Infinite loops in the safety check when no process can finish (use a progress flag)

## 9. Exceptions
Real-world story mode (database locks, printers) · auto-explain "why unsafe" in plain English · HTML report output
